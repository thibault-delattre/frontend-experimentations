Custom Highlight API

Style arbitrary text ranges without injecting spans into prose. The DOM stays stable, selection remains natural, and multiple semantic layers can overlap.

1 · Search results without DOM surgery

Search walks text nodes, creates a Range for every match and registers them as one named Highlight. Try “layout”, “browser”, or “content”.

A resilient interface lets the browser handle layout, scrolling and focus whenever the platform already understands the problem. Custom code should explain product intent, not reconstruct browser behavior.

That division keeps content selectable, links recognizable and layout responsive. It also makes the uncommon states—zoom, translation, reduced motion and keyboard navigation—far less surprising.

2 · Persistent annotations over real prose

Select text inside the passage, choose a colour, then add a note. The Range is cloned before selection collapses and registered without modifying a single text node.

Design quality is often the accumulation of small correct decisions: a label that remains visible, a focus ring that does not shift layout, motion that can be interrupted, and an error message that offers a way forward. None is spectacular alone. Together they make an interface feel trustworthy.

3 · Highlights can become inspectable layers

highlightsFromPoint() returns the highlight objects and ranges under a viewport coordinate. Hover your annotations above to inspect overlapping semantic layers without wrapper hit targets.
