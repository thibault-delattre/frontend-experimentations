Post-Processing Stack

Bloom, chromatic aberration, film grain, vignette and colour grading composed as TSL nodes on a single output node — not as a chain of framebuffer passes. Toggle each one to see what it contributes.

The node approach

The old EffectComposer ran one full-screen pass per effect, each with its own render target. TSL post-processing instead builds a single expression tree and lets the compiler fuse it — most of the stack below collapses into one fragment shader. 

import { RenderPipeline } from 'three/webgpu';
import { pass, uniform, vec3, vec4, screenUV, mix, smoothstep } from 'three/tsl';
import { bloom } from 'three/addons/tsl/display/BloomNode.js';

const post = new RenderPipeline(renderer);

const scenePass = pass(scene, camera);      // the rendered scene, as a node
const colour    = scenePass.getTextureNode();

// bloom() is itself a node: it takes a node in and returns a node out.
const glow = bloom(colour, strength, radius, threshold);

// Everything downstream is ordinary TSL arithmetic on colour.
let out = colour.add(glow);
out = out.mul(vignette).mul(grain);

post.outputNode = out;
post.render();                               // replaces renderer.render()

What each effect is doing

  • Bloom — threshold the image to keep only what is brighter than 1.0, downsample it through a mip chain, blur each level, then add them back. That is why bloom needs HDR: with values clamped to 1.0 there is nothing above the threshold to bloom, and you get a uniform haze instead of light.
  • Chromatic aberration — sample R, G and B at slightly different radial offsets from the centre. Real lenses do this at the edges, which is why it reads as "photographed" and not as "broken". Keep it under about 0.005 of screen width.
  • Grain — animated hash noise. Its real job is to break up banding in gradients and to hide the compression artefacts in dark areas, not to look retro.
  • Vignette — a radial darkening. The cheapest possible way to draw the eye toward the centre of frame.
  • Grade — saturation is a lerp between the image and its luminance; contrast is a scale about 0.5. Both are two lines and belong at the end of the chain, after tone mapping.

Order matters

Bloom must happen in linear HDR, before tone mapping. Grain and vignette must happen after, in display space — grain applied before tone mapping gets crushed by it, and a vignette applied before will shift hue as it darkens. Getting this wrong is the usual reason a stack "looks muddy".

Cost

Bloom's mip chain is the expensive part — roughly six extra passes at decreasing resolution. On mobile, halve the resolution of the bloom input, or drop bloom and keep only the cheap screen-space effects, which together cost less than one full-screen pass.
