Image Displacement

The award-site transition, from scratch: hover and drag to push the pixels around, click a dot to cross-dissolve through a noise map with chromatic separation. Raw WebGL2, no library.

What the fragment shader actually does

Three ideas stack on top of each other. Each one is two or three lines. 

// 1 · DISPLACE — offset the lookup coordinate by a value read from a map.
//     The map is a texture; its red channel becomes an x/y push.
float d = texture(u_disp, uv).r;
vec2 uvA = uv + normal * (d - 0.5) * strength;

// 2 · SPLIT — sample the three channels at slightly different offsets.
//     This is chromatic aberration: it reads as "lens", not as "glitch".
float r = texture(u_tex, uvA + dir * s * 1.0).r;
float g = texture(u_tex, uvA                ).g;
float b = texture(u_tex, uvA - dir * s * 1.0).b;

// 3 · DISSOLVE — compare the map against the transition progress to get a
//     per-pixel threshold, so the two images tear into each other instead of
//     fading uniformly.
float m = smoothstep(d - 0.08, d + 0.08, progress);
color = mix(colorA, colorB, m);

Details worth copying

  • Cover, not stretch. Images almost never match the canvas aspect. The shader computes a cover UV transform from the two aspect ratios — the same maths as object-fit: cover, done once in the vertex stage.
  • Lerp the pointer, don't read it raw. The displacement centre eases toward the true pointer position each frame (p += (target - p) * 0.08). That single line is the difference between "expensive" and "twitchy".
  • Keep the displacement map low frequency. High frequency noise in a displacement map produces sparkle and aliasing; blur it, or generate it as smooth fbm as this demo does.
  • Premultiply nothing, but do set UNPACK_FLIP_Y_WEBGL — WebGL's texture origin is bottom-left and every image you load is top-left. Forgetting it is the classic upside-down-texture bug.
