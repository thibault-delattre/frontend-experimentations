Loading & Empty States

The screens most products treat as an afterthought, and where a surprising amount of perceived quality lives. The recurring theme: a skeleton must match the geometry of what replaces it, and every threshold below is a real number, not a taste call.

1 · Three states, one geometry toggle them

The same component rendered as skeleton, loaded and error. Flip between them and watch the box: nothing moves. The skeleton bars inherit the same line-height and the avatar the same diameter, from shared custom properties.

A skeleton whose bars are a different height from the text, or whose card is shorter than the loaded one, produces a jolt at exactly the moment the user starts reading. That jolt is worse than showing nothing at all.

2 · The thresholds numbers, not vibes

How long a request takes should decide what you show. These are the established perceptual bands — click each to simulate a response of that duration.

The two rules people miss: a delay before showing (do not flash a spinner for a 60ms request) and a minimum display time once it is shown (do not flash it away after 30ms either). Together they turn a flickering mess into something that reads as deliberate. 

let spinner = null;
// Only show the spinner if we are still waiting after 100ms…
const delay = setTimeout(() => { spinner = show(); shownAt = Date.now(); }, 100);

const data = await fetch(…);
clearTimeout(delay);

// …and once shown, keep it up for at least 500ms.
if (spinner) {
  const elapsed = Date.now() - shownAt;
  if (elapsed < 500) await sleep(500 - elapsed);
  hide(spinner);
}

3 · Progress that does not lie determinate vs. indeterminate

If you know the total, show it. If you do not, an indeterminate bar is honest and a fake percentage is not — users notice a bar that sits at 90% forever, and they stop trusting every bar afterwards.

4 · Optimistic UI and a visible rollback

Update the interface immediately and reconcile with the server afterwards. The half nobody implements is the failure path: if the request fails, the revert must be visible, or the user walks away believing something happened that did not.

5 · Streaming show what has arrived

When results arrive incrementally, render them incrementally. A user reading the first three rows does not care that the last seven are still in flight.

    Accessibility usually skipped entirely

    • aria-busy="true" on the region while it loads, so assistive tech knows the content is in flux.
    • role="status" with aria-live="polite" to announce completion. Not assertive — that interrupts whatever the user is reading.
    • A spinner needs an accessible name. A bare spinning div announces nothing at all; give it aria-label="Loading".
    • Skeletons should be aria-hidden="true". Announcing twelve empty grey boxes is worse than announcing nothing.
    • <progress> or role="progressbar" with aria-valuenow/min/max for determinate progress.
