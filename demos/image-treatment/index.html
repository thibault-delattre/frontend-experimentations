Image Treatment

How arbitrary imagery is made to look art-directed. Almost all of it is blend modes and masks — and every "photograph" here is painted procedurally into a canvas, so the page ships no assets.

1 · Duotone two ways

The CSS version desaturates then composites a gradient in color blend mode. The SVG version maps each channel through its own transfer curve, which lands shadows and highlights on genuinely different colours rather than tinting uniformly.

2 · Blend modes what each is actually for

The same gradient over the same image, eight ways. These are not interchangeable looks — each one preserves something different.

3 · Masks fade to nothing

mask-image uses a gradient's alpha as a stencil. It is how an image fades into the page rather than ending at a hard rectangle — and it works over any background, which a gradient overlay does not.

Always write both -webkit-mask-image and mask-image. Omit the prefix and older Safari shows the image completely unmasked — a silent failure, not a visible one.

4 · clip-path reveals hover or focus

clip-path is compositor-friendly, so these wipes are free. Both cards are focusable, so the reveal is reachable by keyboard — :focus-within alongside :hover.

The Ken Burns image starts at scale: 1.15, not 1. Any translate at scale 1 drags the image's own edge into frame — the most common bug in this effect.

5 · Sibling dimming with :has() no JavaScript

The container asks "am I containing a hovered child?" and restyles all of them. This used to require a mouseenter listener and a class on the parent. 

.gallery:has(.frame:hover) .frame       { filter: grayscale(1) brightness(.55); }
.gallery:has(.frame:hover) .frame:hover { filter: none; scale: 1.03; }

6 · Progressive reveal blur-up

A tiny blurred placeholder cross-fades to the full image once it has actually decoded. Use img.decode() rather than the load event — load fires before the bitmap is ready to paint, so you can still get a blank frame. 

const img = new Image();
img.src = full;
await img.decode();        // NOT onload — decode() waits for a paintable bitmap
wrapper.classList.add('loaded');

The layout rules that matter more than any of this

  • Always reserve the box. width and height attributes on the <img>, or aspect-ratio on its frame. Without it the page reflows when each image arrives, which is most of a bad CLS score.
  • object-fit: cover plus object-position so the crop is deliberate. The default centre crop decapitates people.
  • loading="lazy" below the fold, fetchpriority="high" on the LCP image. Lazy- loading the hero is a classic self-inflicted wound.
  • Never bake text into an image. It cannot be selected, translated, searched or read aloud, and it blurs on zoom.
