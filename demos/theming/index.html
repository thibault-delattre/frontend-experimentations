The three tiers

1 · Primitives

Raw scale values. No meaning attached, identical in every theme.

--blue-500: oklch(62% .19 265);
--grey-900: oklch(17% .014 265);
2 · Semantic

Roles. This is the layer that flips per theme, and the only one components may reference.

--ui-surface: var(--grey-0);
--ui-accent: var(--blue-600);
3 · Component

Consumption. If a component names a primitive, the theme cannot move it.

.card { background: var(--ui-surface); }

The one rule that matters: a component may never reference a primitive. The moment a card says background: var(--grey-0) it is hardcoded to light mode, and no amount of theming will save it.

Dark mode is not an inversion

Notice that --ui-shadow and --ui-rim change shape between themes, not just value. Light mode gets a soft cast shadow; dark mode gets a one-pixel rim highlight and a much tighter shadow, because on a near-black page a shadow has nothing to darken. Reusing a light-mode elevation scale in dark mode is the most common reason dark themes look flat. 

[data-theme='light'] {
  --ui-shadow: 0 1px 2px …/.08, 0 8px 20px …/.07;
  --ui-rim: none;
}
[data-theme='dark'] {
  --ui-shadow: 0 1px 2px oklch(0% 0 0 / .5);
  --ui-rim: inset 0 1px 0 oklch(100% 0 0 / .07);   /* ← the lit edge */
}

The flash of wrong theme

The switcher writes to localStorage, but reading it in a module script is too late — modules are deferred, so they run after first paint and the user sees a flash of the wrong theme. The fix is a small synchronous inline script in <head>, before any stylesheet. 

<head>
  <script>                          <!-- inline, sync, FIRST -->
    const s = localStorage.getItem('theme') || 'system';
    const dark = s === 'dark' ||
      (s === 'system' && matchMedia('(prefers-color-scheme: dark)').matches);
    document.documentElement.dataset.theme = dark ? 'dark' : 'light';
  </script>
  <link rel="stylesheet" …>
</head>

Also set color-scheme per theme. Without it the browser keeps styling scrollbars, date pickers and the canvas behind your page for the opposite theme — the classic "dark site, blinding white scrollbar" bug.

light-dark(), for the simple cases

When a value only needs two variants and you are already declaring color-scheme, light-dark() removes the duplicated block entirely. It is not a replacement for semantic tokens — it is a shortcut inside them. 

:root { color-scheme: light dark; }
.card {
  background: light-dark(var(--grey-0), var(--grey-900));
  color:      light-dark(var(--grey-900), var(--grey-50));
}
