Layout Primitives

Six layouts that respond to the space they are given, not to the width of the window — so zero media queries. Drag the handle at the bottom-right of each dashed box to resize its container and watch the layout change while the window stays put.

1 · Stack the owl selector

Vertical flow with one gap value. Margin goes only between children, so the first child never contributes a stray gap and you never write :last-child { margin: 0 }. 

.stack > * + * { margin-block-start: var(--space); }

2 · Cluster wrap gracefully

For tag lists, button rows and metadata — anything where the item count is unknown and wrapping must not look broken.

3 · Sidebar content-derived wrapping

The one that justifies the whole approach. The main pane declares a minimum width; when the container can no longer honour it, the aside wraps to its own line. The breakpoint is a property of the content, so this component behaves correctly inside a modal, a column or a full-width page without knowing where it is. 

.sidebar > :last-child {
  flex-basis: 0;
  flex-grow: 999;              /* eat all remaining space */
  min-inline-size: 55%;        /* …until this cannot be met, then wrap */
}
AsideFixed 16rem basis. Wraps to full width when the main pane runs out of room.
Mainflex-grow: 999 and a 55% minimum. Drag the handle left until this cannot be satisfied — the aside jumps above, all at once.

4 · Switcher all-or-nothing

A row that flips to a column in one step, with no half-wrapped intermediate state where two items share a line and the third sits alone. 

.switcher > * {
  flex-grow: 1;
  flex-basis: calc((var(--threshold) - 100%) * 999);
}

When the container is narrower than the threshold the expression is a huge positive number, so every item claims a full line. When it is wider the value goes negative, is clamped to zero, and the items share one line. The multiplier just saturates it past any real size.

6 · Reel scroll + snap

A horizontal row with snap points, contained overscroll so it does not trigger browser back-navigation, and items that keep their size.

7 · auto-fit vs auto-fill the one everyone gets wrong

Identical declarations except for one word, and they behave differently only when there are fewer items than fit. Widen both. 

grid-template-columns: repeat(auto-fit,  minmax(11rem, 1fr));
grid-template-columns: repeat(auto-fill, minmax(11rem, 1fr));

Use auto-fit when items should fill the row — galleries, dashboards. Use auto-fill when a consistent item size matters more than filling the space, such as a product grid where a stretched lone card looks wrong.

When a media query is still right

  • Page-level structure — whether the site has a sidebar at all, not how that sidebar behaves.
  • Device capability — hover, pointer, prefers-reduced-motion, prefers-color-scheme. These describe the user, and no container knows about them.
  • Print.

Everything about how a component arranges itself belongs to the component and its container. That is the whole distinction.
