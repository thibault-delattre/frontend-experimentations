Tabs & Navigation State

Tabs are a composite keyboard widget, not a row of unrelated buttons. Activation strategy depends on latency; URL state depends on whether the content deserves a link.

1 · Automatic activation for instant panels

Arrow focus immediately selects because every panel is already local. One shared indicator measures the active tab, so selection reads as movement rather than unrelated background fades.

One active layer

Tab enters the selected tab. Arrow keys move inside the tablist; the next Tab reaches panel content.

Shared geometry

The indicator reads offsetLeft and offsetWidth after fonts settle and whenever the container resizes.

2 · Manual activation when panels are latent

Arrow keys only preview focus. Enter or Space commits selection and starts the simulated request, so keyboard exploration never triggers expensive network work.

3 · Addressable tab selection

Selection is mirrored in ?section= with history.replaceState, and popstate restores it. Use this only when a panel is meaningful enough to bookmark or share.

The first tabset updates the URL as you select Overview, Mechanics, or Accessibility. Reloading or sharing that URL preserves the chosen section.
