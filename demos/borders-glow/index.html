Borders & Glow

CSS cannot paint a gradient into border-width. Everything below is a way around that — and the mask-composite: exclude trick in §2 is the one that generalises to every case, including rounded corners and transparent backgrounds.

1 · background-clip pair the simple one

Two background layers with different clip boxes, and a transparent border to reveal the lower one. Well supported and cheap — but the card can never be see-through, because the top layer must be opaque.

padding-box + border-boxOpaque fill required.
border: 2px solid transparent;
background:
  linear-gradient(var(--bg), var(--bg)) padding-box,
  linear-gradient(135deg, …)            border-box;

2 · mask-composite the general one

A pseudo-element painted with the gradient, then masked so only the ring survives. Two mask layers — one covering the whole box, one covering just the content box — composited with exclude, which subtracts the second from the first.

Transparent insideThe page shows through the card.
&::before {
  inset: 0; border-radius: inherit;
  padding: 2px;                     /* the border width */
  background: linear-gradient(135deg, …);
  mask: linear-gradient(#000 0 0) content-box,   /* inner region */
        linear-gradient(#000 0 0);               /* whole box    */
  mask-composite: exclude;          /* whole − inner = the ring */
  -webkit-mask-composite: xor;      /* Safari's older keyword   */
}

border-radius: inherit is doing quiet work here: it keeps the ring's curvature locked to the card's, so changing one radius never leaves a mismatched outline.

3 · Rotating conic needs @property

A conic gradient whose start angle animates. This is impossible without registering the custom property — an unregistered --angle is an opaque string, and CSS will jump straight from one value to the next with no interpolation.

Registered <angle>Now it can be tweened.
@property --angle {
  syntax: '<angle>';
  inherits: false;
  initial-value: 0deg;
}
@keyframes spin { to { --angle: 360deg; } }

4 · Spotlight grid one listener, many cards

Move the pointer across the grid. Both the surface wash and the border highlight read the same --mx/--my, written by a single delegated listener on the container — not one per card.

5 · The rim highlight dark-mode depth

A one-pixel light line along the top edge. On dark surfaces this does more for perceived depth than any shadow, because it reads as an edge catching light rather than as an object casting shade.

Border onlyFlat. Ambiguous edges.
+ inset top highlightSuddenly it has a top surface.
+ gradient + bottom shadeFully modelled.
box-shadow:
  inset 0  1px 0 oklch(100% 0 0 / 0.11),   /* lit top edge   */
  inset 0 -1px 0 oklch(0%   0 0 / 0.30),   /* shaded bottom  */
  0 1px 2px  oklch(0% 0 0 / 0.5),
  0 8px 22px oklch(0% 0 0 / 0.3);

6 · Marching dashes SVG, not CSS

CSS dashed borders cannot be animated and break at rounded corners. An SVG rect with rx and an animated stroke-dashoffset handles both correctly.

Drop zoneDashes march around the radius.

7 · Glow & focus two things people get wrong

A glow must never be a filter on the element itself — that blurs the text too. Put a blurred, scaled copy behind it.

Hover for glowText stays perfectly sharp.

And a focus ring must be an outline, never a border. Tab between these two:

outline is painted outside the box and does not participate in layout, so it cannot shift anything. outline-offset then gives it breathing room without a wrapper element.
