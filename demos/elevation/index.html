Shadows, Light & Depth

A single box-shadow always reads as cheap, because real penumbra is not a straight ramp. Everything below is about approximating the falloff and keeping one light source honest across a whole interface.

1 · One shadow vs. six

Same apparent height, same colour, same corner radius. The only difference is that the right-hand card stacks six shadows whose blur doubles and whose opacity halves at each step.

2 · An elevation ramp

Six levels generated from one function, so the whole scale stays internally consistent. Ship them as custom properties and never write an ad-hoc shadow again.

Levels map to meaning, not to taste: 0 flush, 1 cards, 2 raised buttons, 3 dropdowns, 4 modals, 5 anything dragged. If two components have the same importance they get the same level.

4 · Shadows are not black

A pure black shadow desaturates whatever it falls on and reads as dirt. A shadow carrying the surface's own hue at low lightness reads as light.

5 · The contact shadow

A tight, dark, almost unblurred shadow directly beneath the object. Without it a card appears to hover a centimetre off the page; with it the same card is resting on it. One extra line.

6 · Inset — pressed and recessed

The same principle inverted. A pressed control gains an inner shadow and loses its outer one; a well or track is permanently inset.

A recessed well — inset shadow, no outer shadow, slightly darker fill.

7 · Dark mode changes the rules

On a dark surface there is nothing for a shadow to darken. Elevation has to come from a lighter fill, and the thing that actually sells it is a one-pixel rim highlight along the top edge — a lit edge, not a cast shadow.

Shadow onlyBarely reads. This is what happens when a light-mode shadow scale is reused unchanged.
Lighter fillBetter — but flat, and the edges are ambiguous.
Fill + rim + shadowThe inset top highlight is doing most of the work here.
box-shadow:
  inset 0 1px 0 oklch(100% 0 0 / 0.07),   /* the rim — this is the one */
  0 1px 2px  oklch(0% 0 0 / 0.4),
  0 8px 20px oklch(0% 0 0 / 0.35);

8 · Never animate box-shadow

box-shadow is not a compositor property, so transitioning it repaints the element every frame. Put the raised shadow on a pseudo-element and cross-fade its opacity instead — the visual result is identical and it runs on the GPU. Hover the card.

hover me
.card::after {
  content: ''; position: absolute; inset: 0; border-radius: inherit;
  box-shadow: /* the RAISED shadow */;
  opacity: 0; transition: opacity .25s;
}
.card:hover::after { opacity: 1; }   /* composited, no repaint */
