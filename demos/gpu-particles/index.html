GPU Compute Particles

A quarter of a million particles, integrated entirely in a WebGPU compute shader. Positions and velocities live in GPU storage buffers and are never read back — the CPU's only job per frame is to dispatch and draw.

The compute pipeline

Two storage buffers and two kernels. One kernel seeds the buffers once; the other advances them every frame. Neither ever touches JavaScript. 

import { instancedArray, Fn, instanceIndex, hash, deltaTime } from 'three/tsl';

// 1 · STATE — allocated on the GPU, never mapped back to the CPU.
const positions  = instancedArray(COUNT, 'vec3');
const velocities = instancedArray(COUNT, 'vec3');

// 2 · INIT — one invocation per particle, dispatched once.
const init = Fn(() => {
  const p = positions.element(instanceIndex);
  p.assign(vec3(hash(instanceIndex), hash(instanceIndex.add(1)), …).sub(0.5).mul(8));
})().compute(COUNT);
await renderer.computeAsync(init);

// 3 · UPDATE — dispatched once per frame, before the draw.
const update = Fn(() => {
  const p = positions.element(instanceIndex);
  const v = velocities.element(instanceIndex);
  v.addAssign(curl(p).mul(deltaTime));          // the whole simulation
  v.mulAssign(damping);
  p.addAssign(v.mul(deltaTime));
})().compute(COUNT);

// 4 · DRAW — the render material reads the same buffer as a vertex attribute.
material.positionNode = positions.toAttribute();

Why this is a different order of magnitude

  • No round trip. A CPU particle system must write every position into a buffer and upload it each frame. At 250k particles that is 3 MB of bus traffic per frame, before any maths. Here the data is already where it is needed.
  • Genuine parallelism. The dispatch runs in workgroups across every compute unit at once. The same integration loop that takes ~30ms on one JavaScript thread finishes in under 2ms.
  • WebGPU only. WebGL2 has no compute stage. The historical workaround is "ping-pong" rendering — encode state into a float texture, render to another, swap — which still works but is awkward and limited to what a fragment shader can express.

The force fields

  • Curl noise — take the curl of a noise vector field. Because a curl is divergence-free by construction, particles swirl without ever bunching up or thinning out. This is the standard field for smoke, dust and magic.
  • Attractor — the Lorenz system, integrated per particle. Each one traces the same strange attractor from a different starting point.
  • Vortex — tangential force around an axis with radial falloff, plus gravity toward the plane.
  • Gravity wells — inverse-square attraction to a few moving points, softened at the core so nothing goes to infinity.

Additive blending, no depth write

Particle systems are painted with AdditiveBlending and depthWrite: false. Overlapping particles then sum toward white, which is what light actually does, and there is no sorting problem because addition is commutative.
