Scroll-Driven Animations

This entire page contains no JavaScript beyond the top bar. Every motion below is a CSS @keyframes whose playhead is the scroll position rather than the clock. Read the <style> block — it is the whole tutorial.

The two primitives are scroll() (progress of a scroll container) and view() (progress of an element through the viewport), selected with animation-timeline and windowed with animation-range.

1 · Reveal on enter

animation-timeline: view() with animation-range: entry 5% entry 60%. Scrub the scrollbar slowly — the fade is genuinely tied to position, so it runs backwards when you scroll up. An IntersectionObserver cannot do that.

5 · Scroll-triggered

animation-trigger plays a normal timed animation when a range is crossed — play-forwards going down, play-backwards coming back up — instead of scrubbing it. Use it when you want a spring or an ease that should not be dragged. If your browser lacks it, this box simply sits still.

Gotchas worth remembering

  • Wrap in @supports (animation-timeline: view()) so the from state never becomes a permanent opacity: 0 in an unsupporting browser.
  • overflow: hidden makes an element a scroll container and can capture the timeline you meant to reach — overflow: clip does not.
  • Animate transform, translate, scale, opacity and filter. Anything that triggers layout will drop frames on the scroll thread.
  • Honour prefers-reduced-motion: scrubbed motion is still motion.
