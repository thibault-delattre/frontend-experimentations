2 · Bezier editor drag the handles

A cubic-bezier(x1, y1, x2, y2) is two control points. X must stay in 0–1 (time cannot run backwards); Y is unbounded, which is exactly how you get anticipation and overshoot.

preview

Drag the first handle below the baseline for anticipation — the element pulls back before it moves. Drag the second above the top for overshoot.

3 · Springs no duration at all

A spring is defined by stiffness, damping and mass. It has no duration — it settles when the physics say so. The damping ratio ζ = c / (2√(km)) classifies the whole behaviour.

spring preview

That linear() string is the spring sampled into CSS keypoints — it runs a real spring with no JavaScript at all.

4 · Interruption the argument for springs

Press toggle repeatedly, fast. The eased ball restarts from zero velocity every time and visibly stutters. The spring carries its current velocity into the new target and stays smooth. This is the single strongest practical reason to use springs for anything a user can interrupt.

5 · steps() for things that should not glide

Sprite sheets, typewriters, segment counters and anything discrete. steps(n, end) holds each value rather than interpolating.

Scale duration with distance. A tooltip appearing 8px away and a drawer sliding 400px should never share a duration. A reasonable heuristic: duration ≈ 120 + distance × 0.6 ms, clamped to 150–500ms.

  • 0–100ms — reads as instant. Hover states.
  • 100–300ms — most UI state changes.
  • 300–500ms — modals, drawers, page-level moves.
  • >500ms — only when the user is explicitly waiting.
  • Never linear for movement. Nothing physical starts and stops instantaneously, so it reads as mechanical every time.
