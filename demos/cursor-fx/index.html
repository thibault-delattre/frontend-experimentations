Cursor & Pointer

A custom cursor is a fixed element eased toward the real pointer. The dot must track exactly; the ring must lag. That lag is the whole effect — a 1:1 follow reads as broken, and too much lag reads as unresponsive.

This device has no fine pointer (or you have asked for reduced motion), so every effect on this page has correctly disabled itself and the native cursor is untouched. That fallback is not an afterthought — it is the requirement.

1 · Context awareness data-cursor

The ring reads a data-cursor attribute from whatever is under the pointer, rather than matching a hardcoded list of selectors. Adding a new interactive element means adding one attribute, not editing the cursor code.

2 · Magnetic buttons proximity pull

Within ~110px the button eases toward the cursor and its label moves slightly further — that parallax between the two is what makes it read as attraction rather than as drift.

The rules that make this shippable

  • Gate everything behind matchMedia('(hover: hover) and (pointer: fine)'). On touch, hybrid and stylus devices, leave the native cursor alone and disable the lot.
  • Never cursor: none on body. Scope it to the elements you have actually replaced. If your script fails to load, a global rule leaves the user with no cursor at all.
  • Keep the native cursor over text inputs and any resize or drag affordance the OS already communicates well.
  • A custom cursor is never the only affordance. Everything it reacts to must also have a visible hover state and be reachable and operable by keyboard.
  • Honour prefers-reduced-motion — a lagging, springing follower is exactly the kind of motion that setting exists to suppress.
  • mix-blend-mode is not free. It creates a stacking context and forces a compositing pass over whatever is beneath. Fine for one small element; do not scatter it. 
const fine = matchMedia('(hover: hover) and (pointer: fine)');
const still = matchMedia('(prefers-reduced-motion: reduce)');
if (!fine.matches || still.matches) return;   // ← before anything else

// lerp toward the target; the LAG is the effect
ring.x += (pointer.x - ring.x) * 0.15;
ring.y += (pointer.y - ring.y) * 0.15;
