Customizable Select

The native select finally has a styleable button, top-layer picker, rich options and selected-content clone—without giving up form submission or platform keyboard behavior.

1 · Rich options, native semantics

Options can carry visual hierarchy and decoration. The value still comes from the option’s explicit value, and unsupported browsers fall back to an ordinary functional select.

Submitted value: webgpu

2 · Selected content is a clone

<selectedcontent> clones the chosen option into the closed button. Descendants can be hidden there without changing the richer picker row—but later mutations to the original option are not automatically recloned.

Change the backend above and watch the compact closed state preserve only the useful summary.

3 · Picker adapts without a replacement widget

This icon-first picker grows toward intrinsic width on hover or keyboard focus via calc-size() when available. It remains one native select throughout.
